# Rules learned from the battery, and what was done about them

Written after scoring, never before. This is the operational half of the
experiment: what the run turned up that is worth changing in the business.

Do not put any of this into `key/answer_key.csv`. That file is frozen evidence
and adding a row to it after a run means scoring against a key that was edited
once the answers were known. Findings live here instead.

Each entry records the rule in plain language, the candidate it came from so it
can be traced back to the evidence, and what was actually done. The last column
is the one that matters in a year.

| Candidate | Rule as now understood | Conditions | Status |
| --- | --- | --- | --- |
| p03-exclusivity-person | Guides assigned to a trip may also run that trip's shuttles. | Only at defined drop and pickup points, at set times. Does not require extra staff. | not yet written into the SOPs |

Status is one of: not yet written into the SOPs, added to the SOPs, added to
the conflict checker, rejected on reflection.

A rule that reaches "rejected on reflection" stays in the table. Knowing which
findings did not survive a second look is worth as much as knowing which did.
